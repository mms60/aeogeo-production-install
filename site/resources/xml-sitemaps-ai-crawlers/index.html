XML Sitemaps and Crawl Depth for AI Crawlers

By AEOGEO Search

Quick answer

A sitemap lists the URLs you want crawled and the date each one changed. For AI crawlers working with limited time, an accurate sitemap plus shallow internal links decides which pages get fetched at all.

AI crawlers do not wander a site the way a person does. They start from a known URL, follow links, and stop when their budget runs out. A sitemap shortens that path. It tells the crawler what exists, which version is canonical, and when it last changed.

Sitemap hygiene that matters

  • Include only 200-status, indexable, canonical URLs.
  • Exclude redirects, 404s, noindex pages and parameter duplicates.
  • Set lastmod only when the content changed, not on every deploy.
  • Keep each file under 50,000 URLs and 50 MB, and use a sitemap index when you need more.
  • Reference the sitemap in robots.txt and submit it in Search Console and Bing Webmaster Tools.

Why lastmod is the field crawlers trust least

If every URL gets today's date on every deploy, the field becomes noise and crawlers learn to ignore it. A sitemap that reports real edits gets re-fetched more efficiently, which matters when a page changes and you want the new version cited.

Crawl depth is the other half

A page four clicks from the homepage may never be fetched by a crawler with a small budget. Keep important pages within three clicks, link them from a hub, and use descriptive anchors. Orphan pages that exist only in the sitemap are discovered slowly, if at all.

Internal links that help machines

  • Link related guides to each other with descriptive anchor text.
  • Use real anchor elements, not JavaScript-only menus.
  • Keep breadcrumbs visible and marked up.
  • Avoid nofollow on internal links you want followed.

Server behavior decides the rest

A sitemap cannot compensate for slow or unstable responses. Pages that time out, redirect chains, cookie walls and soft 404s all waste the crawler's budget. Check status codes, response time and the initial HTML before adding more URLs.

A monthly check

Compare the sitemap against Search Console coverage, remove URLs that no longer return 200, confirm lastmod values match real edits, and spot-check that key pages are reachable in three clicks. That routine catches most crawl problems before they show up as missing citations.

Single file or sitemap index

A single sitemap is easiest to submit and debug. Once you pass a few thousand URLs, or you want separate files per section, use a sitemap index that points to child sitemaps. Keep each child focused, for example guides, services and location pages, so a failure is easy to isolate.

When a page is missing from the index

A URL in the sitemap is a request, not a guarantee. If a page is not indexed, check the status code, the canonical, the robots meta tag and whether the content is reachable by links. Then request indexing in Search Console or Bing Webmaster Tools. Adding the URL again does nothing if the page itself is the problem.

What AI crawlers do with sitemaps

Not every AI crawler reads sitemaps, and those that do may treat them as one input among several. The sitemap still helps because it is machine-readable, cheap to parse and explicit about lastmod. Pair it with internal links so a crawler that ignores sitemaps can still find the page.

Priority and changefreq

Google has said it ignores priority and changefreq. Other crawlers may read them, but no major system relies on them. Spend the effort on accurate lastmod and clean URLs instead.

The goal is not a bigger sitemap. It is a smaller, more accurate map of the pages you want read.

Key takeaways

  • Only canonical, indexable 200 pages belong in the sitemap.
  • Accurate lastmod beats frequent lastmod.
  • Important pages should be three clicks from the homepage.
