llms.txt Explained: The Emerging AI Crawler Standard

By AEOGEO Search

Quick answer

llms.txt is a proposed Markdown file at /llms.txt that lists a site's most useful pages with short descriptions. It is not an official standard and no major AI provider guarantees reading it. Treat it as a cheap clarity layer, not a visibility switch.

The idea is simple: give a language model a curated index of your site in plain Markdown, so it does not have to infer which pages matter from navigation and HTML. The proposal was published in September 2024 by Jeremy Howard of Answer.AI. It has since been adopted by some documentation sites and ignored by others.

What the file looks like

The convention is a Markdown file with an H1 for the project name, a blockquote summary, then H2 sections containing links and one-line notes. A companion llms-full.txt can hold the full text of key pages for systems that want more than a map.

What it can do

  • State which pages are canonical when several cover the same topic.
  • Point to documentation, pricing and policy pages that are easy to miss in navigation.
  • Give a short, quotable description of the business in plain language.

What it cannot do

  • Guarantee that any model reads it.
  • Replace robots.txt, sitemaps or structured data.
  • Protect content or control training.
  • Rank a page or earn a citation on its own.

Who should publish one

Sites with a large, documentation-heavy library benefit most, because a curated index reduces the chance that a model picks an outdated page. Small sites with a dozen pages gain little; their sitemap and internal links already describe the structure. If your pages change often, an unmaintained llms.txt becomes another stale source of truth.

A minimal example

Start with the business name, one sentence on what you do and who you serve, then three to six sections such as Guides, Services, Pricing and Policies. Link only live, canonical URLs, and keep each note under one line. Put the file at the site root and serve it as text/plain or text/markdown.

Measure it honestly

AI crawler logs rarely identify llms.txt reads, and referral data will not isolate its effect. Treat it as an experiment with a low cost. Publish it, keep it current, and judge it by whether the pages you point to are the pages that get cited.

How it fits with sitemaps and structured data

A sitemap lists URLs. Structured data describes entities and page types. robots.txt sets crawl rules. llms.txt describes priority and meaning in prose. If the other three are wrong, llms.txt will not repair them. If they are right, it adds a small amount of clarity about which pages matter most.

Common mistakes

  • Listing every URL instead of a curated set.
  • Linking pages that have moved, merged or been retired.
  • Using marketing language where a description belongs.
  • Repeating the same section for several topics.
  • Serving the file behind authentication or client-side rendering.
  • Expecting a ranking effect from the file itself.

Keeping it current

Review the file when you publish or retire a major page. Ten accurate links beat a hundred stale ones. Add a date line if your process supports it, and keep the file out of the sitemap. The point is a short, trustworthy map, not another index to maintain.

How to tell whether it is read

Server logs may show requests for /llms.txt, but most AI crawlers do not advertise their purpose and some fetch through proxies. Treat a request as a weak signal, not proof that a model used the file. The stronger signal is whether the pages you list are the pages that get cited.

The file is a clarity aid. The work that moves visibility is still the content it points to.

Key takeaways

  • llms.txt is a 2024 proposal, not an official standard.
  • It helps most on large documentation libraries with clear canonical pages.
  • It does not replace sitemaps, robots.txt or structured data.
